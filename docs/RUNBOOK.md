# GYMOS Runbook

This runbook is the operator checklist for running GYMOS locally on Windows 11 with Docker Desktop and PowerShell. Run commands from the repository root unless a step says otherwise.

## 1. Prerequisites

Install and start:

- Docker Desktop using Linux containers.
- Node.js 22.x (the project supports Node.js `>=20.19.0 <23`).
- npm 10 or newer.
- Git.

Verify versions and Docker Compose:

```powershell
node --version
npm --version
docker --version
docker compose version
```

## 2. Get the project

For a new machine:

```powershell
git clone https://github.com/Jafar19Khan/GYMOS.git
Set-Location GYMOS
```

For an existing checkout:

```powershell
git switch main
git pull --ff-only
```

Check that Docker Desktop is running:

```powershell
docker info
```

## 3. Configure the environment

Create the local environment file once:

```powershell
Copy-Item .env.example .env
notepad .env
```

Set these values in `.env`:

1. `POSTGRES_PASSWORD`: use a strong, unique local database password. To avoid URL-encoding problems, use a hexadecimal value generated by the command below.
2. `DATABASE_URL`: host-side URL; keep the hostname as `localhost`.
3. `DATABASE_URL_DOCKER`: container-side URL; keep the hostname as `db`.
4. `BOOTSTRAP_OWNER_EMAIL` and `BOOTSTRAP_OWNER_PASSWORD`: set both to create the initial gym owner. Use a unique password of at least 12 characters and no more than 72 UTF-8 bytes.
5. `ATTENDANCE_QR_SECRET`: set a private random value to enable QR attendance.
6. Keep `TRUST_PROXY_HEADERS=false` for a direct local setup.

Generate values in PowerShell:

```powershell
$DbPassword = node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
$QrSecret = node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
$DbPassword
$QrSecret
```

Paste the database password into `POSTGRES_PASSWORD` and use the exact same password in both database URLs:

```text
DATABASE_URL=postgresql://gymos:<DB_PASSWORD>@localhost:5432/gymos?schema=public
DATABASE_URL_DOCKER=postgresql://gymos:<DB_PASSWORD>@db:5432/gymos?schema=public
```

Paste the QR value into `ATTENDANCE_QR_SECRET`. Set the owner email and password too. Save `.env`.

If local port 5432 is already in use, set `POSTGRES_HOST_PORT=55432` in `.env` and change the port in `DATABASE_URL` to `55432`. Do not change the port in `DATABASE_URL_DOCKER`; containers connect to PostgreSQL on port 5432 inside the Compose network.

Never commit or share `.env`, database passwords, QR signing secrets, bootstrap credentials or database backups.

## 4. First-time startup

Build and start the database and web application:

```powershell
docker compose -f docker/compose.yaml up --build -d --wait --wait-timeout 180
```

The web container waits for PostgreSQL, applies all committed Prisma migrations, and then starts the Next.js server. Check both services:

```powershell
docker compose -f docker/compose.yaml ps
```

Install host dependencies and create the initial owner account:

```powershell
npm install
npm run db:seed
```

The seed command only creates the owner when both bootstrap owner variables are configured. It does not create a default account or password. Running it again is safe for an already-created matching bootstrap account.

## 5. Verify the application

Check service health and database readiness:

```powershell
Invoke-RestMethod http://localhost:3000/api/health
Invoke-RestMethod http://localhost:3000/api/ready
```

Both endpoints should return successfully. Then open the login page:

```powershell
Start-Process http://localhost:3000/login
```

Sign in with the bootstrap owner credentials. QR attendance scanning requires browser camera permission and a secure browser context; `localhost` is supported for local testing.

## 6. Normal daily commands

Start existing containers:

```powershell
docker compose -f docker/compose.yaml up -d --wait --wait-timeout 180
```

View service status and logs:

```powershell
docker compose -f docker/compose.yaml ps
docker compose -f docker/compose.yaml logs --tail 100 web
docker compose -f docker/compose.yaml logs --tail 100 db
```

Follow web logs live:

```powershell
docker compose -f docker/compose.yaml logs -f web
```

After pulling code changes, rebuild and restart:

```powershell
git pull --ff-only
docker compose -f docker/compose.yaml up --build -d --wait --wait-timeout 180
```

Committed database migrations are applied by the web container during startup. Do not manually edit migration history in the database.

## 7. Run in development mode (optional)

Use this mode when actively changing application code. Keep PostgreSQL in Docker and run Next.js on the host:

```powershell
docker compose -f docker/compose.yaml up -d db
npm install
npm run db:generate
npm run db:deploy
npm run dev
```

Open http://localhost:3000. Stop the development server with `Ctrl+C`. Do not run the production web container and host development server on the same port simultaneously.

## 8. Quality checks

Run these from the repository root:

```powershell
npx prisma validate
npm run db:generate
npm run lint
npm run typecheck
npm run test
npm run build
```

The GitHub Actions CI also builds the production Docker image and runs a Compose health/readiness smoke test. A successful local build alone does not replace that container smoke test.

## 9. Backup and restore

Create a compressed PostgreSQL backup:

```powershell
./scripts/backup.ps1
```

Restore a backup into the current Compose database (this replaces current database contents):

```powershell
./scripts/restore.ps1 -BackupFile .\backups\gymos-YYYYMMDD-HHMMSS.dump
```

The restore script requires typing `RESTORE`. Store backups outside Git, restrict access to them, and periodically test a restore into a separate database. A Docker volume is not a backup.

## 10. Stop and restart safely

Stop containers but preserve the database volume:

```powershell
docker compose -f docker/compose.yaml down
```

Start again later:

```powershell
docker compose -f docker/compose.yaml up -d --wait --wait-timeout 180
```

**Do not run `docker compose down -v` for normal shutdown.** The `-v` option deletes the PostgreSQL data volume and permanently removes the local database contents.

## 11. Troubleshooting

**Web container is unhealthy or exits**

```powershell
docker compose -f docker/compose.yaml ps
docker compose -f docker/compose.yaml logs --tail 200 web
docker compose -f docker/compose.yaml logs --tail 200 db
```

Resolve the first startup error shown in the web log, then rebuild:

```powershell
docker compose -f docker/compose.yaml up --build -d --wait --wait-timeout 180
```

**Port 3000 or 5432 is already allocated**

Find the process using the port, stop it if appropriate, or change `WEB_HOST_PORT` / `POSTGRES_HOST_PORT` in `.env`. When changing the PostgreSQL host port, update the port in `DATABASE_URL` as described above.

**Database authentication or connection error**

Check that `POSTGRES_USER`, `POSTGRES_DB` and `POSTGRES_PASSWORD` match the credentials in both database URLs. The host URL must use `localhost`; the Compose web URL must use `db`. After changing database credentials on an already-initialized volume, remember that PostgreSQL does not reinitialize an existing data directory from new environment values.

**Login does not work**

Confirm that `BOOTSTRAP_OWNER_EMAIL` and `BOOTSTRAP_OWNER_PASSWORD` were both set before running `npm run db:seed`. Check the seed output. Do not expect a default admin or owner account.

**QR attendance is unavailable**

Confirm that `ATTENDANCE_QR_SECRET` is set, restart the web service after changing it, and allow camera access in the browser. Use `localhost` or HTTPS.

## 12. Operational limits

This release is suitable for local evaluation and controlled testing, not a production launch. Payment records are manual (no payment gateway), invitation links are shared manually (no email provider), the website CMS has no media upload, and MFA/account recovery, external monitoring, broader E2E/security testing and cloud deployment approval remain outstanding. See [Security](SECURITY.md), [Operations](OPERATIONS.md) and [Roadmap](ROADMAP.md) before any production deployment.
